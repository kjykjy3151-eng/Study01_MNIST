# 손글씨 인식 앱을 웹 버전과 데스크톱 버전으로 분리 — 설계

## 1. 목적과 성공 기준

손글씨 숫자 인식 앱을 두 갈래로 나눈다. 기존 파이썬/Tkinter 앱은
`desktop_version/` 으로 옮기고, 설치 없이 브라우저에서 바로 쓸 수 있는
웹 버전을 `web_version/` 에 새로 만든다.

웹 버전의 목적은 **설치 없는 채점, 시연**이다. 교수님이나 다른 사람이 링크만
열어 바로 써 볼 수 있어야 한다. 이 목적에서 따라 나오는 성공 기준은 다음과 같다.

1. 웹 버전이 데스크톱 버전과 **같은 가중치, 같은 전처리 규칙**을 쓴다.
   같은 그림을 넣으면 같은 숫자를 예측한다.
2. 외부 자바스크립트 라이브러리를 하나도 쓰지 않는다. 빌드 단계도 없다.
3. GitHub Pages에 정적 파일만 올려 동작한다. 서버도, CI도 필요 없다.
4. 데스크톱 버전은 폴더 이동 뒤에도 지금과 똑같이 동작한다.
5. 위 1번이 주장이 아니라 **실행 가능한 검증**으로 뒷받침된다.

## 2. 현재 상태와 제약

기존 코드는 `model.py` → `train.py` / `app.py` 순으로 의존한다. 학습과 추론이
같은 모델 구조와 같은 정규화 상수(`평균 = 0.1307`, `표준편차 = 0.3081`)를
공유하는 것이 이 코드베이스의 핵심 제약이며, 웹 버전도 이 제약 안에 들어온다.

모델 구조와 파라미터 수는 다음과 같다.

| 층 | 모양 | 파라미터 수 |
| --- | --- | --- |
| 합성곱1 | (32, 1, 3, 3) + (32) | 320 |
| 합성곱2 | (64, 32, 3, 3) + (64) | 18,496 |
| 완전연결1 | (128, 9216) + (128) | 1,179,776 |
| 완전연결2 | (10, 128) + (10) | 1,290 |
| **합계** | | **1,199,882** |

float32로 내보내면 4,799,528바이트(약 4.6MB)다. 대부분이 완전연결1 층이다.

추론 1회의 곱셈누산 횟수는 합성곱1이 약 19만, 합성곱2가 약 1,060만,
완전연결1이 약 118만으로 도합 약 1,200만 회다. 순수 자바스크립트에
`Float32Array` 를 쓰면 일반 노트북에서 수십 밀리초에 끝나므로, WebAssembly나
WebGL 없이 평범한 반복문으로 충분하다.

### 이동이 건드리는 것들

실행 스크립트 세 개(`.bat`, `.command`, `.ps1`)와 `app.가상환경으로_재실행()`
은 모두 **자기 파일 옆의 `.venv`** 를 찾는다. 한편 웹 가중치를 내보내는
스크립트도 `mnist_cnn.pt` 를 읽으려면 torch가 필요하다. 따라서 `.venv` 는
저장소 루트에 그대로 두어 두 버전이 공유하고, 데스크톱 쪽 네 곳이 상위 폴더의
`.venv` 를 보도록 고친다. 가상환경을 옮기지 않으므로 다시 만들 필요도 없다.

### 검증

- `desktop_version` 폴더에서 `..\.venv\Scripts\python.exe app.py` 로 창이 뜨고 인식이 된다.
- `.bat` 더블클릭으로 실행된다.
- `python -c "import sys; sys.platform='darwin'"` 방식의 맥 분기 확인은 기존 방법을 유지한다.

## 5. web_version

### 5.1 가중치 내보내기 — `도구/가중치_내보내기.py`

`../desktop_version/mnist_cnn.pt` 를 읽어 두 파일을 만든다. torch만 쓰고
루트 `.venv` 로 실행한다.

`가중치/mnist_cnn.bin` 은 리틀엔디언 float32를 아래 순서로 이어 붙인 원시
바이너리다. 헤더가 없으므로 자바스크립트가 `Float32Array` 뷰로 바로 읽는다.

```
합성곱1.weight (32,1,3,3) → 합성곱1.bias (32)
→ 합성곱2.weight (64,32,3,3) → 합성곱2.bias (64)
→ 완전연결1.weight (128,9216) → 완전연결1.bias (128)
→ 완전연결2.weight (10,128) → 완전연결2.bias (10)
```

`가중치/구조.json` 은 각 텐서의 이름, 모양, 시작 오프셋, 길이와 정규화 상수
(`평균`, `표준편차`), 내보낸 시각을 담는다. 자바스크립트는 이 파일만 보고
바이너리를 자른다. 층 모양이 바뀌어도 JSON만 갱신하면 되도록 이름을 키로 쓴다.

내보내기 스크립트는 파일 크기가 기대값 4,799,528바이트와 다르면 오류를 낸다.

### 5.2 `js/전처리.js`

데스크톱 `app.전처리()` 와 같은 일을 한다. **DOM에 의존하지 않는 순수 함수**로
만든다. 그래야 브라우저 없이 Node에서 그대로 시험할 수 있다.

```
전처리(회색조, 너비, 높이) -> Float32Array(784) | null
```

`회색조` 는 0~255 `Uint8Array` 이고, 검은 배경에 흰 글씨다. 절차는 데스크톱과
같다.

1. 0이 아닌 픽셀의 경계 상자를 찾는다. 없으면 `null` 을 돌려준다.
2. 경계 상자를 잘라, 가로세로 비율을 유지한 채 긴 변이 20픽셀이 되도록 축소한다.
3. 28×28 검은 도화지 한가운데에 붙인다.
4. 픽셀 밝기의 무게중심을 구해 정수 픽셀 단위로 (13.5, 13.5)에 맞춰 평행 이동한다.
5. 255로 나눠 0.0~1.0으로 돌려준다. 정규화는 호출한 쪽에서 한다.

#### 축소 보간을 직접 구현하는 이유

2단계에서 데스크톱은 PIL의 `Image.LANCZOS` 를 쓴다. 브라우저의 `drawImage`
축소 보간은 명세가 없어 브라우저마다 결과가 다르므로, 그대로 쓰면 "데스크톱과
같은 인식률"을 보장할 수 없다. PIL의 축소 규칙을 자바스크립트로 옮긴다.

PIL은 축소할 때 필터 폭을 축소 배율만큼 넓히는 안티에일리어싱 방식을 쓴다.
가로 방향을 먼저 처리하고 그 결과를 세로 방향으로 다시 처리하는 분리형이며,
중간 결과를 8비트로 반올림해 저장한다. 한 축에 대한 계수 계산은 다음과 같다.

```
배율        = 입력크기 / 출력크기
필터배율    = max(1, 배율)
지지폭      = 3 * 필터배율            (Lanczos3)
각 출력 픽셀 xx 에 대해
    중심    = (xx + 0.5) * 배율
    시작    = max(floor(중심 - 지지폭 + 0.5), 0)
    끝      = min(floor(중심 + 지지폭 + 0.5), 입력크기)
    가중치[x] = 란초스((x + 시작 - 중심 + 0.5) / 필터배율)
    가중치 합이 1이 되도록 정규화
란초스(t) = 1                          (t = 0)
          = sinc(t) * sinc(t/3)        (|t| < 3)
          = 0                          (그 밖)
sinc(t) = sin(pi t) / (pi t)
```

두 축 사이에서 값을 반올림하고 0~255로 자르는 것까지 PIL과 맞춘다. 부동소수점
누산 순서 차이로 ±1 정도의 오차는 남을 수 있으며, 이 오차는 예측 숫자를 바꾸지
않는다. 검증 단계에서 이 전제를 실제로 확인한다.

### 5.3 `js/모델.js`

`구조.json` 과 `mnist_cnn.bin` 을 `fetch` 로 받아 순전파를 수행한다.
드롭아웃은 추론 시 항등 함수이므로 구현하지 않는다.

```
모델_불러오기(기준경로) -> Promise<모델>
모델.예측(정규화된_784_Float32Array) -> Float32Array(10)   // 0~1 확률
```

연산 순서는 `model.숫자인식CNN.forward` 와 같다.

```
(1,28,28)
→ 합성곱 3x3 무패딩 + ReLU        → (32,26,26)
→ 합성곱 3x3 무패딩 + ReLU        → (64,24,24)
→ 최대풀링 2x2                    → (64,12,12)
→ 평탄화 (채널, 행, 열 순)        → (9216)
→ 완전연결 + ReLU                 → (128)
→ 완전연결                        → (10)
→ 소프트맥스                      → (10)
```

평탄화 순서가 어긋나면 완전연결1의 가중치가 엉뚱한 픽셀에 곱해져 결과가 조용히
망가진다. PyTorch의 `torch.flatten(x, 1)` 과 같게 `채널 * 144 + 행 * 12 + 열`
순서로 편다.

로그 소프트맥스 뒤 지수를 취하는 대신 소프트맥스를 직접 계산하되, 최댓값을 빼고
지수를 취해 오버플로를 막는다. 결과는 두 방식이 같다.

### 5.4 `js/앱.js` 와 화면

데스크톱 앱과 같은 구성이다. 왼쪽에 280×280 검은 캔버스, 오른쪽에 예측 숫자,
확신도, 0~9 확률 막대, 모델이 실제로 보는 28×28 미리보기를 놓는다.

- 붓 굵기 22픽셀, 흰색, 둥근 끝. 데스크톱과 같은 값이라 축소했을 때 두께가 맞는다.
- 포인터 이벤트(`pointerdown` / `pointermove` / `pointerup`)를 써서 마우스와
  터치를 한 경로로 받는다. 캔버스에 `touch-action: none` 을 준다.
- 손을 떼면 바로 인식한다. 지우기 버튼과 Esc 키, 다시 인식 버튼을 둔다.
- 가중치 4.6MB를 받는 동안 "모델을 불러오는 중입니다." 를 표시하고 캔버스 입력을
  막는다. 받기에 실패하면 화면에 오류 문구를 남긴다.
- 캔버스에서 `getImageData` 로 꺼낸 RGBA를 회색조 `Uint8Array` 로 바꿔
  `전처리()` 에 넘긴다. 검은 배경에 흰 글씨만 그리므로 R 채널만 읽으면 된다.

### 5.5 검증 — `테스트/`

두 단계로 나눠 확인한다. 나누는 이유는, 결과가 틀렸을 때 추론이 틀렸는지
전처리가 틀렸는지 바로 가려내기 위해서다.

`테스트/골든_만들기.py` 가 루트 `.venv` 로 실행되어 MNIST 평가셋 앞 200장으로
아래 파일을 만든다. 저장소에 올라가는 크기는 다 합쳐 약 330KB다.

| 파일 | 내용 |
| --- | --- |
| `골든/원본_28.bin` | 200 × 784 uint8. MNIST 원본 |
| `골든/전처리_28.bin` | 200 × 784 uint8. 파이썬 전처리를 거친 결과 |
| `골든/확률.bin` | 200 × 10 float32. PyTorch 출력 확률 |
| `골든/예측.bin` | 200 uint8. PyTorch 예측 숫자 |

원본 28×28을 최근접 이웃으로 10배 확대해 280×280 캔버스 그림을 만들고, 그것을
전처리에 넣는다. 확대는 파이썬과 자바스크립트가 똑같이 할 수 있는 단순한
연산이라, 캔버스 그림 자체를 저장소에 넣지 않아도 양쪽이 같은 입력에서 출발한다.

이 스크립트는 전처리 코드를 복사하지 않고 `sys.path` 에 `desktop_version` 을
넣어 `from app import 전처리` 로 **데스크톱 구현을 그대로 불러다 쓴다.** 복사해
두면 데스크톱 쪽이 바뀌었을 때 골든 데이터만 옛 규칙에 머물러, 검증이 통과하는데
실제 두 앱은 다르게 동작하는 상황이 생긴다. `app.py` 는 `__main__` 일 때만
가상환경 재실행을 하므로 import 해도 부작용이 없다.

`테스트/검증.mjs` 를 `node 테스트/검증.mjs` 로 돌려 다음을 확인한다. 외부 패키지
없이 Node 기본 모듈만 쓴다.

1. **추론 검증** — `전처리_28.bin` 을 그대로 정규화해 `모델.예측()` 에 넣고,
   `확률.bin` 과 비교한다. 확률 최대 오차 1e-4 이내, 예측 숫자 200개 전부 일치.
2. **전처리 검증** — `원본_28.bin` 을 10배 확대해 `전처리()` 에 넣고,
   `전처리_28.bin` 과 비교한다. 픽셀 최대 오차 2/255 이내.
3. **통합 검증** — 2단계 결과를 1단계 모델에 넣어 얻은 예측이 `예측.bin` 과
   200개 전부 일치.

1번이 깨지면 가중치 읽기나 순전파가 틀린 것이고, 2번이 깨지면 Lanczos 구현이
틀린 것이다. 3번이 이 프로젝트가 실제로 주장하려는 바, 곧 "웹 버전이 데스크톱과
같은 답을 낸다" 를 직접 확인한다.

구현은 이 세 시험을 먼저 쓰고 통과시키는 순서로 진행한다.

## 6. GitHub Pages 배포

Pages를 `main` 브랜치 루트로 설정한다. 워크플로 파일도, 빌드도 없다.

- 웹 앱 주소는 `https://<계정>.github.io/study01_MNIST/web_version/` 이다.
- 저장소 루트의 `index.html` 은 `web_version/` 으로 보내는 리다이렉트만 담아,
  `https://<계정>.github.io/study01_MNIST/` 로 들어와도 열리게 한다.
- 루트에 빈 `.nojekyll` 을 둬서 Jekyll 처리를 건너뛴다.
- `web_version/` 안의 모든 경로는 상대 경로로 쓴다. 절대 경로(`/js/...`)를 쓰면
  저장소 이름이 붙는 Pages 주소에서 깨진다.
- `.gitattributes` 에 `*.bin binary` 를 더한다. 줄바꿈 변환이 들어가면 가중치가
  조용히 망가진다.

## 7. CLAUDE.md 세 개의 역할

내용을 겹쳐 쓰지 않고 역할을 나눈다. 세 파일 모두 이 저장소의 한글 작성 규칙을
따른다.

- **루트 `CLAUDE.md`** — 두 버전이 무엇이고 어디에 있는지, `.venv` 를 루트에서
  공유한다는 점, 그리고 **모델 구조와 정규화 상수를 바꾸면 세 곳(학습, 데스크톱
  추론, 웹 가중치)을 함께 고쳐야 한다**는 저장소 전체의 제약을 적는다. 각 버전의
  세부는 해당 폴더 문서로 넘긴다.
- **`desktop_version/CLAUDE.md`** — 지금의 CLAUDE.md 내용을 옮기고 경로만
  갱신한다. 환경, 크로스 플랫폼 규칙, 더블클릭 실행 구조, 윈도우 함정이 그대로
  유효하다.
- **`web_version/CLAUDE.md`** — 외부 라이브러리 금지와 빌드 없음이라는 제약,
  가중치 바이너리의 형식과 다시 만드는 방법, 전처리가 데스크톱과 같아야 한다는
  점, 검증 실행 방법(`node 테스트/검증.mjs`), Pages 배포 시 상대 경로 규칙을
  적는다.

`CLAUDE_전역.md` 는 전역 지침 사본이므로 루트에 그대로 둔다.

## 8. 범위 밖

다음은 이번 작업에서 하지 않는다. 필요해지면 따로 다룬다.

- 가중치 float16 양자화나 경량 모델 재학습. 4.6MB는 한 번 받으면 캐시되며,
  지금 줄이면 "데스크톱과 같은 모델"이라는 성공 기준만 흐려진다.
- 웹 워커, WebAssembly, WebGL. 추론이 수십 밀리초라 필요 없다.
- 오프라인 지원(PWA), 여러 숫자 동시 인식, 그림 저장 기능.
- 웹에서의 학습. 학습은 데스크톱 버전에만 둔다.
- 데스크톱 코드의 리팩터링. 이동과 경로 수정 외에는 건드리지 않는다.

## 9. 위험 요소

| 위험 | 대응 |
| --- | --- |
| Lanczos 재구현이 PIL과 어긋나 인식률이 떨어진다 | 5.5의 2번, 3번 시험이 바로 잡아낸다. 시험을 먼저 쓴다 |
| 완전연결1의 평탄화 순서를 틀린다 | 5.5의 1번 시험이 잡아낸다 |
| 한글 폴더명, 파일명이 Pages 주소에서 문제를 일으킨다 | 기존 저장소가 이미 한글 파일명을 쓰고 있고 UTF-8 경로는 정상 처리된다. 실제 배포에서 문제가 확인되면 웹 자원만 영문명으로 바꾼다 |
| `.venv` 경로 수정을 빠뜨려 데스크톱 실행이 깨진다 | 4장의 네 곳을 목록으로 두고, 이동 뒤 `.bat` 더블클릭까지 실제로 확인한다 |
| 가중치 바이너리가 줄바꿈 변환으로 손상된다 | `.gitattributes` 에 `*.bin binary` 추가. 내보내기 스크립트가 크기를 검사한다 |

## 10. 작업 순서

1. `desktop_version/` 으로 이동하고 경로 네 곳을 고친 뒤 실행을 확인한다.
2. 가중치를 내보내고 크기와 JSON을 확인한다.
3. 골든 데이터를 만들고 `검증.mjs` 의 세 시험을 먼저 쓴다. 이 시점에는 실패한다.
4. `모델.js` 를 구현해 1번 시험을 통과시킨다.
5. `전처리.js` 를 구현해 2번, 3번 시험을 통과시킨다.
6. `index.html`, `스타일.css`, `앱.js` 로 화면을 붙이고 브라우저에서 확인한다.
7. 루트 리다이렉트, `.nojekyll`, `.gitattributes`, `.gitignore` 를 정리한다.
8. CLAUDE.md 세 개와 README를 갱신한다.

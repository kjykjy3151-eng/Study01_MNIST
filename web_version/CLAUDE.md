# CLAUDE.md — 웹 버전

브라우저에서 도는 손글씨 숫자 인식기다. 저장소 전체 규칙은 `../CLAUDE.md`,
데스크톱 버전은 `../desktop_version/CLAUDE.md` 를 보라.

## 지켜야 할 제약

- **외부 자바스크립트 라이브러리를 쓰지 않는다.** 빌드 단계도, 번들러도,
  패키지 파일도 없다. 브라우저가 파일을 그대로 읽는다.
- **모든 경로는 상대 경로다.** `/js/...` 같은 절대 경로는 저장소 이름이
  붙는 GitHub Pages 주소에서 깨진다.
- 코드, 주석, 화면 문구, 직접 정의하는 이름은 한글로 쓴다. 완결된 문장인
  화면 문구와 오류 메시지는 마침표로 끝낸다.

## 구조

| 파일 | 책임 |
| --- | --- |
| `js/모델.js` | 가중치 적재와 순전파. DOM 비의존 |
| `js/전처리.js` | 회색조 배열 → 28×28. DOM 비의존, 순수 함수 |
| `js/앱.js` | 캔버스 입력과 화면 갱신. DOM 의존부는 여기에만 |
| `가중치/mnist_cnn.bin` | float32 원시 바이너리, 4,799,528 바이트 |
| `가중치/구조.json` | 텐서 이름, 모양, 오프셋과 정규화 상수 |
| `도구/가중치_내보내기.py` | `.pt` → `.bin` 변환 (개발용) |
| `테스트/골든_만들기.py` | 파이썬 쪽 정답 데이터 생성 (개발용) |
| `테스트/검증.mjs` | 데스크톱과 같은 답을 내는지 확인 |

`모델.js` 와 `전처리.js` 가 DOM 에 의존하지 않는 것이 이 구조의 핵심이다.
그래야 브라우저 없이 Node 에서 시험할 수 있다. **이 성질을 깨뜨리지 말라.**

## 명령

검증 (외부 패키지 없이 Node 만 필요. 시험 7개, 약 10초):

```bash
node 테스트/검증.mjs
```

가중치 다시 만들기 (데스크톱에서 재학습한 뒤):

```bash
cd 도구 && ../../desktop_version/.venv/Scripts/python.exe 가중치_내보내기.py
```

골든 데이터 다시 만들기 (전처리 규칙을 바꾼 뒤):

```bash
cd 테스트 && ../../desktop_version/.venv/Scripts/python.exe 골든_만들기.py
```

로컬에서 띄워 보기 (ES 모듈과 fetch 는 `file://` 에서 동작하지 않는다):

```bash
../desktop_version/.venv/Scripts/python.exe -m http.server 8000
```

## 검증이 무엇을 보장하는가

`테스트/검증.mjs` 의 시험 일곱 개는 MNIST 평가셋 앞 200장으로 다음을 확인한다.

1. 같은 28×28 입력에서 PyTorch 와 같은 확률 (오차 1e-4 이내, 예측 200개 일치)
2. 같은 그림에서 파이썬 전처리와 같은 28×28 (픽셀 오차 2/255 이내)
3. 전처리부터 추론까지 이어 붙인 예측 200개 일치
4~7. 빈 캔버스, 점 하나, 극단적 종횡비, 꽉 채운 캔버스

1번이 깨지면 가중치 읽기나 순전파가, 2번이 깨지면 Lanczos 구현이 틀린 것이다.

## 전처리가 까다로운 이유

`js/전처리.js` 는 `../desktop_version/app.py` 의 `전처리()` 와 **같은 결과를
내야 한다.** 다음 세 가지가 어긋나기 쉽다.

1. **PIL 의 Lanczos 는 축소할 때 필터 폭을 배율만큼 넓힌다.** 이 처리를
   빼면 계단 현상이 남아 인식률이 떨어진다. 브라우저의 `drawImage` 축소
   보간은 명세가 없어 브라우저마다 결과가 다르므로 쓰지 않는다.
2. **파이썬 `round()` 는 0.5 를 짝수 쪽으로 보낸다.** 자바스크립트
   `Math.round` 는 위로 올리므로, 크기와 이동량 계산에는 `짝수_반올림()` 을
   쓴다.
3. **PIL 은 가로를 먼저 줄이고 8비트로 반올림한 뒤 세로를 줄인다.**
   한 번에 2차원으로 계산하면 값이 달라진다.

한쪽을 고치면 반드시 `골든_만들기.py` 를 다시 돌리고 검증을 통과시켜라.

## 알려진 차이

캔버스는 선을 안티에일리어싱해 그리고, 데스크톱의 PIL `ImageDraw` 는 경계가
딱 떨어지게 그린다. 그래서 **같은 마우스 궤적이라도 두 앱의 입력 그림은
픽셀 단위로 조금 다르다.** 뒤이은 20픽셀 축소가 어차피 부드럽게 만들기
때문에 인식 결과에는 영향이 없고, 검증은 양쪽이 똑같이 만들 수 있는
입력(MNIST 원본을 10배 확대한 그림)으로 하므로 알고리즘 동등성은 그대로
증명된다.

측정해 보면 파이썬 전처리와의 차이는 156,800 픽셀 중 4개가 1/255 만큼일
뿐이고, 최종 예측은 200개가 모두 같다.
